# AI 行为规则

> 规则 ID: CORE-AI-001 ~ CORE-AI-005
> 严重级别: error（全部强制）

## CORE-AI-001: 不得编造不存在的接口、类或配置

AI 在生成代码时：
- 不得虚构不存在的 API 方法、类名、配置项或注解。
- 不确定某个 API 是否存在时，必须明确说明"请验证此 API 是否存在"。
- 不得凭空编造第三方库的方法签名。

**违反示例**:
```java
// 错误：虚构了不存在的方法
orderService.processAndCache(orderId, cacheKey);
```

## CORE-AI-002: 修改代码前必须理解需求

- 修改代码前，必须阅读并理解当前任务的完整需求。
- 必须阅读相关已有代码，理解现有设计意图。
- 不得在未理解上下文的情况下"猜测式修改"。

## CORE-AI-003: 只修改完成当前任务所需的范围

- 不得引入与当前任务无关的代码变更。
- 不得"顺手"重构、格式化或重命名无关代码。
- 不得修改未涉及的配置文件。
- 如发现需要额外修改才能完成任务，应先说明原因并获得确认。

## CORE-AI-004: 修改后应执行必要的编译和测试

- 代码变更完成后，必须执行编译验证。
- 必须运行与变更相关的单元测试。
- 编译或测试失败时，必须停止并报告错误，不得继续后续操作。
- 不得为了"通过测试"而修改测试用例的断言。

## CORE-AI-005: AI 生成内容必须接受人工评审

- 所有 AI 生成的代码必须经过人工评审后才能合并。
- AI 不得自动执行 `git merge`、`git push` 到主分支。
- AI 不得自动创建 Pull Request 并自行合并。
- 评审关注点：逻辑正确性、安全性、性能、可维护性。
