# 数据库规范

> 来源：Team Harness V1.0 PRD §6.1。AI 生成 SQL / DDL 前必须自检以下项。

## 1. 索引合理性

- 评估 `WHERE` / `JOIN` / `ORDER BY` 涉及的列是否需要索引。
- 区分度低的列（如 `status` 仅 0/1）不单独建索引，纳入组合索引。
- 组合索引列顺序遵循最左前缀原则。

## 2. 避免全表扫描（强制）

- 禁止无 `WHERE` 的查询 / 更新 / 删除。
- 禁止在索引列上做函数运算或隐式类型转换（会导致索引失效）。
- 避免 `LIKE '%xxx'` 左模糊（不走索引）。

## 3. 禁止 SELECT *（强制）

- 明确列出所需列名，减少 IO 与不必要的字段暴露。

## 4. 大数据量分页（强制）

- 禁止深分页 `LIMIT offset, n`（offset 越大越慢）。
- 深分页改用游标 / 延迟关联 / 主键范围：`WHERE id > :lastId LIMIT n`。

## 5. DDL 变更

- 任何 DDL 变更必须先输出完整 SQL 供人工审核（安全红线，见 `security.md`）。
- 表与字段必须加注释；字符集统一 `utf8mb4`。
- 列名避开数据库保留字。
