# 业务说明 — http-service-example

## 业务概述

本项目是一个面向 C 端用户的 HTTP API 服务，核心提供两大业务能力：

1. **用户管理**：用户注册、信息维护、状态管理
2. **订单查询**：订单列表分页查询、订单详情查询

---

## 用户服务

### 领域模型

| 实体 | 说明 | 关键字段 |
|------|------|----------|
| User | 用户主实体 | id, username, phone, email, status, createTime |
| UserProfile | 用户扩展信息 | userId, nickname, avatar, gender, birthday |

### 用户状态机

```
                  注册
                   │
                   ▼
                ┌──────┐
        ┌──────│ACTIVE│──────┐
        │       └──────┘      │
        │ 停用                 │ 删除
        ▼                      ▼
   ┌─────────┐           ┌─────────┐
   │INACTIVE │           │DELETED  │
   └─────────┘           └─────────┘
        │                      │
        │ 重新激活              │ 不可恢复
        ▼                      │
   ┌──────┐                    │
   │ACTIVE│◄───────────────────┘
   └──────┘  （不支持）
```

- `ACTIVE` → `INACTIVE`：管理员停用或用户主动停用
- `INACTIVE` → `ACTIVE`：管理员重新激活
- `ACTIVE`/`INACTIVE` → `DELETED`：软删除，数据保留但不可见
- `DELETED` 状态不可逆，不支持恢复

### 业务规则

1. **注册**：用户名 4-20 字符，仅允许字母、数字、下划线；手机号需符合中国大陆格式
2. **唯一性校验**：用户名全局唯一，手机号全局唯一
3. **查询**：支持按用户名、手机号、状态模糊/精确查询
4. **更新**：仅 `ACTIVE` 状态用户可修改个人信息
5. **停用**：停用后用户不可登录，但历史订单数据保留可查

## 订单服务

### 领域模型

| 实体 | 说明 | 关键字段 |
|------|------|----------|
| Order | 订单主表 | id, orderNo, userId, status, totalAmount, createTime |
| OrderItem | 订单商品明细 | id, orderId, productId, productName, quantity, unitPrice |
| OrderLogistics | 订单物流 | id, orderId, trackingNo, carrier, status |

### 订单状态机

```
┌─────────┐     支付     ┌──────┐     发货     ┌─────────┐     确认收货     ┌───────────┐
│PENDING  │─────────────►│PAID  │─────────────►│SHIPPED  │────────────────►│COMPLETED  │
└─────────┘              └──────┘              └─────────┘                 └───────────┘
     │                      │
     │ 取消                 │ 取消
     ▼                      ▼
┌──────────┐          ┌──────────┐
│CANCELLED │          │CANCELLED │
└──────────┘          └──────────┘
```

### 业务规则

1. **列表查询**：支持按用户 ID、订单状态、时间范围筛选；默认按创建时间倒序
2. **分页**：默认 `pageSize=20`，最大 `pageSize=100`，超过则截断为 100
3. **详情查询**：包含订单基本信息 + 商品明细列表 + 物流信息
4. **权限**：用户只能查询自己的订单，管理员可查询所有订单
5. **数据脱敏**：订单详情中的用户手机号需脱敏（如 `138****8888`）

## API 版本化策略

### 版本管理规则

| 规则 | 说明 |
|------|------|
| 版本化方式 | URL 路径版本化（`/api/v1/...`、`/api/v2/...`） |
| 默认版本 | v1（当前唯一活跃版本） |
| 新版本触发条件 | 接口签名不兼容变更（字段删除/重命名/类型变更） |
| 向后兼容 | 字段新增不视为版本升级（追加式变更兼容） |
| 版本共存上限 | 同一接口最多保留 2 个版本 |
| 版本废弃过渡期 | 旧版本下线前至少保留 3 个月 |
| 废弃标识 | 响应头 `Deprecation: true` + `Sunset: <date>` |

### 版本生命周期

```
v1 发布 → v2 发布（v1 标记废弃）→ 3 个月过渡期 → v1 下线
```

### 版本迁移检查清单

- [ ] 新版本接口已通过测试
- [ ] 旧版本已添加废弃标识头
- [ ] 已通知所有接入方迁移
- [ ] 过渡期满后确认无流量访问旧版本
- [ ] 旧版本代码删除并提交
