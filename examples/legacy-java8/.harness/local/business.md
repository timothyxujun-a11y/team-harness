# 业务说明 — legacy-java8-example

## 业务概述

本项目是基于 Quartz 的定时任务服务，负责日终对账、报表生成、数据归档等批处理业务。

---

## 定时任务清单

### 1. 日终对账（ReconcileJob）

| 属性 | 值 |
|------|----|
| Cron | `0 0 23 * * ?`（每天 23:00） |
| 超时 | 2h |
| 分布式锁 | `job:lock:reconcile:daily`（TTL 2.5h） |
| 重试 | 失败后重试 1 次，间隔 5min |

### 对账流程

```
对账任务启动
    │
    ▼
获取分布式锁
    │
    ├── 失败 ──► 记录 INFO 日志，跳过执行（其他节点正在执行）
    │
    └── 成功
        │
        ▼
    查询当日交易数据总数
        │
        ▼
    分页处理（每页 500 条）
        │
        ├── 逐条对账（本地交易 ↔ 支付渠道回执）
        │     │
        │     ├── 一致 ──► 标记已对账
        │     │
        │     └── 不一致 ──► 记录差异明细
        │
        └── 记录处理进度（支持断点续跑）
        │
        ▼
    汇总对账结果
        │
        ├── 差异率 < 0.01% ──► 正常完成
        │
        └── 差异率 ≥ 0.01% ──► 告警 + 暂停后续报表生成
        │
        ▼
    释放分布式锁
        │
        ▼
    发送执行报告
```

### 对账差异类型

| 类型 | 说明 | 处理方式 |
|------|------|----------|
| 本地多记 | 本地有交易，支付渠道无回执 | 记录差异，人工核查 |
| 本地少记 | 支付渠道有回执，本地无交易 | 记录差异，人工核查 |
| 金额不一致 | 双方都有记录但金额不同 | 记录差异，告警通知 |
| 状态不一致 | 交易状态不一致 | 记录差异，人工核查 |

### 2. 报表生成（ReportJob）

| 属性 | 值 |
|------|----|
| Cron | `0 30 0 * * ?`（每天 00:30） |
| 超时 | 1h |
| 分布式锁 | `job:lock:report:daily`（TTL 1.5h） |
| 依赖 | 日终对账完成（对账差异率 < 阈值） |

### 报表类型

| 报表 | 说明 | 输出格式 |
|------|------|----------|
| 日报表 | 当日交易汇总（按渠道、品类分组） | Excel (.xlsx) |
| 对账差异报表 | 当日对账差异明细 | Excel (.xlsx) |
| 异常交易报表 | 当日异常交易列表 | Excel (.xlsx) |

### 报表生成流程

```
报表任务启动
    │
    ▼
检查前置条件（对账是否完成且差异率达标）
    │
    ├── 不满足 ──► 延迟 10min 后重试（最多 3 次）
    │
    └── 满足
        │
        ▼
    逐个生成报表
        │
        ├── 查询数据（游标查询，避免 OOM）
        │
        ├── 生成 Excel（Apache POI，SXSSFWorkbook 流式写入）
        │
        └── 上传到文件服务器（OSS）
        │
        ▼
    记录报表元信息（名称、路径、生成时间）
        │
        ▼
    发送报表就绪通知
```

### 3. 周报汇总（WeeklyReportJob）

| 属性 | 值 |
|------|----|
| Cron | `0 0 2 ? * MON`（每周一 02:00） |
| 超时 | 3h |
| 分布式锁 | `job:lock:report:weekly`（TTL 3.5h） |
| 依赖 | 上周所有日报表已生成 |

### 4. 月结归档（MonthlyArchiveJob）

| 属性 | 值 |
|------|----|
| Cron | `0 0 3 1 * ?`（每月 1 日 03:00） |
| 超时 | 4h |
| 分布式锁 | `job:lock:archive:monthly`（TTL 4.5h） |

### 归档规则

- 归档上月所有已对账的交易数据到归档表（`archive_transaction_YYYYMM`）
- 归档后删除生产表中已归档的数据（分批删除，每批 1000 条）
- 归档完成后验证数据条数一致性

---

### 5. 数据清理（DataCleanupJob）

| 属性 | 值 |
|------|----|
| Cron | `0 0 4 * * ?`（每天 04:00） |
| 超时 | 30min |
| 分布式锁 | `job:lock:cleanup:daily`（TTL 35min） |

### 清理规则

| 数据 | 保留期限 | 清理方式 |
|------|----------|----------|
| 对账差异明细 | 90 天 | 物理删除 |
| 任务执行日志 | 30 天 | 物理删除 |
| 临时报表文件 | 7 天 | 删除 OSS 文件 |
| 归档表数据 | 3 年 | 超期后物理删除 |

## 批处理策略

### 分页处理

```java
int pageNum = 1;
int pageSize = 500;

while (true) {
    List<Transaction> batch = mapper.selectPage(startId, pageSize);
    if (batch.isEmpty()) {
        break;
    }

    for (Transaction txn : batch) {
        try {
            processSingle(txn);
            successCount++;
        } catch (Exception e) {
            log.error("处理失败, txnId={}, error={}", txn.getId(), e.getMessage(), e);
            failCount++;
            // 不中断，继续处理下一条
        }
        startId = txn.getId();
    }

    // 更新进度（支持断点续跑）
    progressService.save(jobExecutionId, pageNum, successCount, failCount);
    pageNum++;
}
```

### 断点续跑

- 每处理完一批数据后，将进度写入 `job_execution_progress` 表
- 任务重新启动时，检查是否存在未完成的执行记录
- 存在则从断点继续，不存在则从头开始

### 游标查询

- 大数据量报表查询使用 MyBatis Cursor（`@Select` + `Cursor<T>` 返回类型）
- 避免一次性加载全部数据到内存导致 OOM
- 配合 SXSSFWorkbook（Apache POI 流式写入）生成 Excel

## 告警机制

| 告警场景 | 阈值 | 通知方式 |
|----------|------|----------|
| 对账差异率超标 | ≥ 0.01% | 钉钉 + 邮件 |
| 任务执行超时 | 超过配置超时时间 | 钉钉 |
| 任务执行失败 | 重试后仍失败 | 钉钉 + 电话 |
| 批处理失败率超标 | ≥ 1% | 钉钉 |
| 分布式锁获取失败 | 连续 3 次 | 钉钉（提示检查集群状态） |
